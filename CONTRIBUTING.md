# Contribution Guidelines

Thanks for your interest in contributing to Sinytra!

When working on your contribution, please follow the guidelines outlined in this document.
This will also help your contributions get reviewed and merged smoothly!

## Avoid using generative AI

Every pull request must be authored and submitted by a human. Given the nature and complexity of some of our projects,
as well as to ensure the highest possible quality, we explicitly discourage the use of generative AI models for authoring
pull requests, regardless of whether it is used for writing the code or the description.

It is expected that authors understand the problem at hand and can present the pros and cons of the chosen solution.
This should be clear to the maintainers from the PR description.

## Pull request descriptions

Every PR should include a clear description of what it does.
Briefly explain what was added, updated, or fixed, and provide any relevant context for reviewers.

If your PR fixes or relates to an existing issue, reference the issue number in the description (e.g., Fixes #1234)
as this helps maintain traceability and automatically closes issues when the PR is merged.

## Code style

Follow the code style of the repository you're working in.

## Keep pull requests small and focused

We strongly encourage small, focused pull requests over large, sweeping changes.
Bug fixes, QOL improvements, and other incremental contributions are much easier to review and more likely to be merged quickly.

If you’re looking for something to work on, check out the GitHub issues tab for open tasks and known bugs.

## Tips

### Consult people on Discord

There are a number of reasons to want to consult with people on our Discord before making a pull request.
For example, if you’re not sure whether something is a good idea or not, if you’re not sure how to implement something,
or if you can’t get something working, we'll gladly help you out!

If you intend to work on new features or to make significant codebase changes, please consult with us first to ensure your work is put to its best use.

### Don’t get discouraged

At times, pull requests may be rejected or left unmerged for a variation of reasons.
Don’t take it personally, and don’t get discouraged! Sometimes a contribution just isn’t the right fit for the time, or it might have just been lost
in the mess of other things to do. The core team are often busy, whether it be on a specific project/task or on external factors such as offline responsibilities.

It all falls back to the same thing: don’t get discouraged!

### Code isn’t the only way to contribute

You don’t need to know how to program to contribute. Quality assurance, donating, supporting the community, coming up with feature ideas,
and making sure your voice is heard in public decisions are all great ways to contribute to Sinytra.
